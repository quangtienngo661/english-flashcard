### 1.5 The purchase call
- `useSubmitOnce` (`apps/web/src/app-shell/use-submit-once.ts:17-70`) → `api.post('/v1/me/orders', { period_months: Number(months), expected_amount: price, locale }, { idempotencyKey })` (`PlansPage.tsx:226-229`). Payload id `${months}:${price}` (`:234`): same choice after a network error reuses the key; another choice is a new key. 409 in-progress waits `Retry-After` (≤ 3 times); 409 `idempotency-key-abandoned` retries once with a new key.
- Success 201 `{ order_id, checkout_url }` → `setLeaving(true)` and **`window.location.assign(checkout_url)`** (full load to payOS's hosted page; the QR is on payOS's page, the web never draws one) (`:236-237`). Button stays pending while leaving (`:256`).
- Errors (`:238-247`): `ApiError` slug `price-changed` → invalidate `APP_CONFIG_KEY`, text `priceChanged` "Giá vừa đổi, xem lại trước khi mua" (`vi.json:1653`); status 503 or slug `provider-unavailable` → `buyUnavailable` "Chưa tạo được đơn. Thử lại sau ít phút." (`:1654`); anything else → `useErrorMessage()` text (e.g. `App.errors.rate-limited` "Bạn thao tác hơi nhanh. Thử lại sau {seconds, number} giây." — see `vi.json` `App.errors`). The 409 body also carries `current_amount` (ruling Task 11), unused by the web.
- No redirects on this page other than the payOS hand-off. The payOS return/cancel URL is built by the API: `${learnerAppUrl}/${locale}/app/plans/order?order=${id}` (`ENT/orders/orders.service.ts:76`) — **the order route path is part of the API contract.**
