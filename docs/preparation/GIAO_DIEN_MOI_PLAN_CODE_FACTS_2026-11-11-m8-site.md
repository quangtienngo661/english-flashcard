## 11. Risks and open questions for the plan

1. **Deploy blocked by design.** With `PRICES_REQUIRED=1` in `deploy-web.yml` and no API address in that workflow (and no live API), every `main` deploy fails after M8. Decide: set `PRICES_REQUIRED=1` only once `api.wordmet.com` exists (and add `NEXT_PUBLIC_API_BASE_URL` or a dedicated build-only variable to `deploy-web.yml` and `cf-docker.mjs:103`), or keep fallback in deploy until Deploy. The design's "Deploy thật mà API không trả lời → build fail" needs this sequencing written down.
2. **Where the price read lives.** A `fetch` in `SITE/page.tsx` keeps the page static only if Next 16.4.3 does not treat it as dynamic (UNVERIFIED; `assert:render-mode` would catch it). A read in `JsonLd` (site layout) also runs per request on the three `force-dynamic` pages. A generated module written before `next build` (like `gen:og-fonts`) avoids both; it also avoids risk 3.
3. **OpenNext runtime cache.** `open-next.config.ts` is `defineCloudflareConfig()` with no incremental cache. OpenNext docs say the incremental cache stores SSG pages and fetch data, and recommend the Workers Static Assets cache for SSG sites. Whether `/vi` is served from build output or re-rendered on the Worker (re-running any server `fetch`) with this config is UNVERIFIED. If it re-renders, a "build-time" price `fetch` actually runs at request time against `localhost:3000`.
4. **Local builds read real prices.** The e2e build uses `NEXT_PUBLIC_API_BASE_URL=http://localhost:3000`. On a dev machine with the API running (not inside `cf:docker`), it reads the local DB's prices, so e2e/unit tests that pin fallback prices would flake. Pin the read to the fallback in e2e builds, or assert "a price is shown" plus a unit test on the fallback.
5. **Fallback = API defaults test.** Design §10.6 wants a test that the fallback matches `settings.definitions.ts`. That is a cross-package read (`apps/web` test reading `apps/api/src`, ESM `.js` imports) or an API-side test reading the web file. Choose one; the smoke already pins the API side.
6. **Lint vs move.** `site/` may not import `@/app-chrome/*`, yet the landing needs a logo and a theme toggle. Options: Figma's new public logo (`3:14`, same as `AppLogo`) moved to `ui/` or `site/layout/`; `ThemeToggleButton` moved to `ui/` or `site/`. `AppLogo` is used by `TopBar`, `PhoneHeader`, `CardFrame`, so moving it touches app-chrome imports. The dead `ThemeToggle` wrapper and `i18n/navigation.ts` can go with `components/`.
7. **Full-page link into the app.** Public CTAs must stay plain `<a>` (LB3E6, per-document nonce). `ui/ButtonLink` is `next/link`; either add an anchor variant or keep a `site/` link-button.
