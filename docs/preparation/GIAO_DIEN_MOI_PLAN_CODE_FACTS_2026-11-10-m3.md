## 3. API response shapes (code on the branch)

- `GET /v1/groups` → `{items: GroupSummary[]}` (`API/learning/queue/queue.service.ts:17-26,54-85`): `id, name, version, total, today:{priority,due,new}` (caps applied, `:33-40`), `cells:{level,total,due}[]` (one per level 0-5, `:77`), `backlog`, `available:{due,new}`, **`next_lemma: string | null`** (`:23`), **`last_reviewed: { lemma: string | null; at: string } | null`** (`:25`; `at` ISO string `:73`). Sorted by API: priority>0 first, then waiting desc, then name (code-point `<`) (`:82-83`).
  - `next_lemma`: lemma of the first visible of at most 5 candidate cards per group (`rank <= 5`, `queue.queries.ts:152`; order priority → due by `due_date, level, added_at` → new, within today's caps, `:126-149`); sense hidden → next one; all five hidden → `null` even if more cards exist (`queue.service.ts:67-71`). `null` for an empty group or nothing waiting.
  - `last_reviewed`: newest `learning_log kind='review'` row with `group_id` per group (`queue.queries.ts:157-163`); `lemma` null when the sense is no longer visible.
- `GET /v1/groups/:id` → `GroupDetailView = {id,name,version,item_count,created_at,updated_at,removable_items}` (`API/learning/groups/groups.service.ts:15-18,95`). 404 `not-found`. Matches web `GroupDetail` (`groups-api.ts:25-33`).

11. **`next_lemma` is "first visible of five".** If all five candidate cards of a group are hidden senses, `next_lemma` is `null` although cards remain (`queue.queries.ts:152`, `queue.service.ts:67-71`); design §10.5 table ("Thẻ đầu hàng đợi là nghĩa vừa bị ẩn → lấy thẻ kế") holds only up to 5. `last_reviewed.lemma` is nullable and `at` is an ISO string; the design text says `at` without a type.
12. **Ordering differs between API and web.** API sorts priority first, then waiting, then name by code-point (`queue.service.ts:82-83`); web `sortForToday` puts `waiting>0` first, then priority, then waiting, then `localeCompare` (`GroupCard.tsx:17-25`). Both are reused (`use-practice-starter.tsx:67` uses the web one), so the carousel's initial order is the web sort and changes as cards are done (relevant to design §7.4's reason for colour-by-id).
13. **Group colour test ids.** Today fixtures use non-UUID ids (`g-food`, `g1`); `groupColorIndex` must accept any string (design §7.4 pins 7 sample ids; `isId` is not applied on list/Today). ASSUMPTION: API ids are lowercase UUIDs (the `isId` caller lowercases route input, `groups-api.ts:154-156`).
14. **Easing/duration tokens for the carousel are absent.** Only `--ease-out-strong` (in `globals.css:199`, not `web.css`), `--ease-wm-close` (= the `(.4,0,1,1)` curve of the open/close fade), `--blur-wm-*` (6/12/18; the 3.6/7.2 px carousel blurs and 5/9 px stack blurs are not tokens), and `--transition-duration-wm-out/in/close` 160/320/150 ms exist; 620/450/500/700/380/170/340/460/520 ms and the four `(.3,x,.5,1)` curves have no token. `--transition-duration-wm-in` is 320 ms (`web.css:112`) while the motion doc says 340 ms for the page parts (`motion:89`). `check-tailwind-raw` forbids `-[…]` classes and bare `style={…}` without `// raw-ok:` (existing code uses `style=` with `raw-ok` for widths, `TodayPage.tsx:179`), which constrains how per-card `transform/opacity/filter` values are applied.
15. **Prototype vs design a11y.** The prototype lets a click on a side stack switch group (`vong-7-chong-the-tu-dien.html:1046`); design §8.5 (`:517`) makes side stacks `inert` with the centre as the only pressable one. Switching must then come from the arrows, keys, swipe, picker, or an aria-live-announced control. Also design §8.5 wants single-letter `F` ignored in inputs; the prototype ignores keys only for `input, textarea, select` (`:1049`), the app's `N` handler also ignores `[contenteditable="true"]` and `[role="dialog"]` (`add-word-context.tsx:36`).
16. **Roadmap vs layout.** Roadmap row 3 (`plan.md:66`) adds "route loading files for Hôm nay, Nhóm, Một nhóm", but `topic` and `group/backlog` have no listed loading file even though they are M3 routes and also use `FullScreenSpinner` (`min-h-dvh`) inside the chrome today. The shared `loading.app.tsx` stays as the fallback.
17. **Fixed bar overlap.** `TopicPickerPage` already has a fixed bottom bar `bottom-16 … md:bottom-0` (`:188`) above the phone tab bar; 8A and 9A (floating docks) are new for Backlog and Topic. `AddFab` is `bottom-24` and Today-only (the calendar FAB is M6); `AppChrome` main has `pb-28` on phones.
18. **Unused i18n keys remain** in the five namespaces (e.g. `App.today.review|studyAll`, `App.groups.review|studyAgain`, `App.group.review|studyAll|rowsPriority|rowsDue|rowsNew`); `vi.json` and `en.json` have identical key counts for `today 22, groups 47, group 51, deck 4, stages 6, backlog 30, topic 16`. e2e uses `copy.vi.App.{today,groups,…}` keys directly (m2.spec.ts:89-136), so renaming keys breaks e2e.
