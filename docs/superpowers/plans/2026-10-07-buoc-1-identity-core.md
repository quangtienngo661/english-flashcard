**Goal:** Replace Bước 0's fake `RequestUser` seam with real identity: registration, password login, OTP email verification, password change/reset, rotating refresh-token sessions (mobile body + web cookie), profile, and staff roles with permissions.

**Architecture:** A global `CommonModule` provides config, `Clock`, `AppLogger` and `RateLimiter`. A new `IdentityModule` under `apps/api/src/identity/` owns its Prisma models and exports only `IdentityService` plus auth decorators. A global `AuthGuard` verifies HS256 JWTs (via `jose`) without DB reads. Every write to a user's security state runs in one transaction that first takes a per-user advisory lock, re-reads, returns an outcome, commits, and only then becomes an HTTP error; outbound mail runs after commit and after the response finishes. `configureApp()` is shared by `main.ts` and every e2e test.

**Tech Stack:** NestJS 12.1.2 (ESM), Prisma 7.10.0 + `@prisma/adapter-pg`, Postgres 17, Vitest 4 + Testcontainers, `jose` 6.2.12, `argon2` 0.45.1, `nodemailer` 10.0.15, `cookie-parser` 1.4.7, `zod` 4.6.5, Mailpit (`axllent/mailpit`).

## Global Constraints

- Paths are under `apps/api/` unless they start with `docs/` or are repo-root files. Commands run from `apps/api/` in **PowerShell**; values come from `apps/api/.env` (loaded by `process.loadEnvFile()`, Task 1) or `$env:NAME = '...'`.
- ESM: relative imports end in `.js`. JSON fields `snake_case`. Routes under `/v1`.
- New dependencies pinned exactly: `jose@6.2.12`, `argon2@0.45.1`, `nodemailer@10.0.15`, `cookie-parser@1.4.7`, `zod@4.6.5`; dev `@types/nodemailer`, `@types/cookie-parser` at their current exact versions. Prisma stays `7.10.0`.
- Module boundary (D3): only `src/identity/**` touches Identity tables; others call `IdentityService`. `src/common/**` never imports from `src/identity/**`. No Prisma `@relation` across modules.
- Time: every expiry/lock/window decision uses `Clock.now()` computed in code; never Postgres `now()`.
- **Per-user lock (design §4b):** every transaction that writes a user's security state starts with `withUserLock(tx, userId)` and re-reads what it checks afterwards. One lock per user; never also hold `identity.staff_role`.
- **Commit, then error (§4b):** for expected domain denials (wrong code/password, reused/expired token) no exception escapes a `prisma.$transaction` callback after it wrote security state; return a discriminated outcome and throw after commit. Unexpected errors still throw and roll back.
- **Nothing slow inside the lock:** Argon2 hashing/verification and mail sending happen before or after the transaction. Every locked transaction passes `{ timeout: 10_000, maxWait: 5_000 }`.
- **Mail after commit and after response (§4b):** transactions return prepared `MailMessage | null` values; services wrap them as jobs and pass them to `MailDispatcher.afterResponse(res, jobs)`. Controllers that need `res` take it as `@Res({ passthrough: true })`.
- Validation: every handler binds a strict zod schema through the parameter decorator (`@Body({ schema })`, `@Query({ schema })`, `@Param('id', { schema })`); objects use `z.strictObject`. No bare `@Body()`.
- Errors are Problem Details with the slugs of design §7; bad client input is never 500.
- Logs: `AppLogger` levels `info`/`warn`/`error`; never a password, OTP code, token, cookie value, raw IP, plain email of a failed sign-in/reset, or a raw library error `message`.
- Fixed numbers (design §4–§7): Argon2id `memoryCost 19456`, `timeCost 2`, `parallelism 1`; access token TTL `ACCESS_TOKEN_TTL_SECONDS` default 900; refresh token 32 bytes base64url; grace 10 s; idle 90 d; absolute 365 d; 10 active chains; OTP 6 digits, 10 min, 5 attempts, 20 failures / 24 h → lock 24 h; login lock at 10 failures → 15 min; mail budget default 1500/day, warn at 80 %; SMTP phase timeouts 10 s; Argon2 semaphore 4; body limit 100 KB; email ≤ 254; password 8–128 code points after NFC; `device_label` ≤ 100.
- e2e suites that depend on global state (admin counts, staff listing, cleanup, log audit) run on their own database from `createIsolatedDatabase()` (Task 2).
- Commit after every task on `feat/buoc-1-identity-impl`, Conventional Commits, ending with the `Co-Authored-By` line. Never push without being asked.

## Review Focus

1. **Email typed differently at login** (`"  Foo@Example.COM "` after registering `foo@example.com`) must sign in — Task 10.
2. **Two registrations for one new email at the same instant** → exactly one 201 and one 409, one user row, never 500 — Task 10.
3. **Malformed input** (invalid JSON, `email: 42`, missing fields, unknown extra fields, non-UUID path ids, `page_size: 0`) → 400 `validation-failed`, never 500 — Tasks 2, 8, 9, 10, 13.
4. **A refresh request carrying both a body token and a cookie** takes the body (mobile) path deterministically — Task 8.
5. **A valid access token whose user row no longer exists** → `GET /v1/me` 401, not 500 — Task 12.

**Files:**
