# Bước 2 — Content + Pipeline Implementation Plan

> **Status 12/10/2026: approved by the owner** (after the plan review [`../reviews/2026-10-12-buoc-2-plan-review-claude.md`](../reviews/2026-10-12-buoc-2-plan-review-claude.md)); implementation starts with M1.

> **For agentic workers:** execution follows the owner's Codex loop (CLAUDE.md "Execution note"): per task, Codex `gpt-6.1-sol` implements, Codex `gpt-6-astra` (medium effort, read-only) reviews the diff, Claude re-runs build/tests for real and commits. Claude tracks progress with superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let `admin`/`editor` build the vocabulary catalog through the API only (per-operation endpoints plus a combined CSV upload processed by a background worker, with reports, revert, export and bulk publish), and let logged-in learners search and browse published senses read-only.

**Architecture:** Two modules. `ContentModule` (`src/content/`) owns the catalog tables and all catalog rules and exports only `ContentService` (plus constants, pure helpers and one port). `PipelineModule` (`src/content-pipeline/`) owns upload, batches, the shared job framework and export, and writes the catalog only through `ContentService` methods that take a `tx`. One framework (`background_jobs` + lease/`lease_epoch` + reconciler) runs every job type; the API process is a producer, `src/worker.ts` is the consumer. Postgres is the source of truth; Redis only triggers runs.

**Tech Stack:** NestJS 12.1.2 (ESM), Prisma 7.10.0, Postgres 17, Vitest 4 + Testcontainers (Postgres, Mailpit, **Redis**), plus new `bullmq@6.3.12`, `ioredis@6.0.0`, `csv-parse@7.0.3`, dev `@testcontainers/redis@12.2.0`, `@types/multer@2.3.0`. `@nestjs/bullmq` is **not** used (proposal, see "Verified" below).

**Spec:** [`docs/superpowers/specs/2026-10-12-buoc-2-content-pipeline-design.md`](../specs/2026-10-12-buoc-2-content-pipeline-design.md) — the plan argues from it; read the section named in each task. Decisions D1–D20 with trade-offs: [`../decisions/2026-10-12-buoc-2-content-pipeline-decisions.md`](../decisions/2026-10-12-buoc-2-content-pipeline-decisions.md). The design is the build document; `docs/specs/` is background only. Every test name starts with the `B2#`/`B2E#` it proves and **asserts every clause of that criterion's Then**, including persisted state read back by a fresh query after a rejected request.

**Branches:** this plan lives on `docs/buoc-2-plan` (PR into `dev`). Implementation: one branch per milestone cut from the latest `dev` — `feat/buoc-2-m1-content-core`, `feat/buoc-2-m2-pipeline`, `feat/buoc-2-m3-finish` — each ends with the milestone gate (last task of the milestone) and merges to `dev` by PR when the owner asks.

## Global Constraints

- Paths are under `apps/api/` unless they start with `docs/` or are repo-root files. Commands run from `apps/api/` in **PowerShell**. Docker Desktop must be running.
- ESM: relative imports end in `.js`. JSON fields `snake_case`. Routes under `/v1`. Zod `z.strictObject` schemas bound with `@Body({ schema })`/`@Query({ schema })`/`@Param({ schema })`; no bare `@Body()`. Bad client input is 400 `validation-failed`, never 500.
- New dependencies pinned exactly (`pnpm add -E`): versions in the Tech Stack line above. Prisma stays `7.10.0`.
- **Module boundary (D3):** only `src/content/**` touches content tables; only `src/content-pipeline/**` touches pipeline tables; Pipeline imports from Content **only** through `src/content/index.ts`. No Prisma `@relation` across modules (relations inside one module are fine; cross-module references are plain uuid columns). `src/common/**` never imports from `src/content*/**` or `src/identity/**`.
- **Per-key lock:** every transaction that writes an entry or its senses first takes `pg_advisory_xact_lock(hashtextextended('content.entry:' || lemma || ':' || pos, 0))` (`ContentService.lockEntryKey`), whether it comes from the API or the importer. Inside a job, `ctx.tx` takes a **share** lock on the job row first, then the entry key; heartbeat and acquire lock only the job row and never an entry key, so no cycle exists.
- **Time:** every expiry/lease decision uses `Clock.now()`; tests move `FakeClock`. Never Postgres `now()` for lease logic.
- **Errors:** Problem Details with slugs of design §11 (`source-incomplete`, `level-source-required`, `file-invalid`, `file-too-large`, `publish-incomplete`, `stale-revision`, `export-too-large`, `batch-not-revertable`, `profile-incomplete`) plus the generic `validation-failed`, `forbidden`, `not-found`. Row-level errors are **not** HTTP errors; they live in the batch report with the codes of design §5.
- **Logs:** `AppLogger` only; batch logs carry `operation_id`, counts, duration; **never a cell value**, file content or context sentence.
- **Permissions:** `content.edit`, `content.publish`, `content.import`, `taxonomy.manage` for both `admin` and `editor`; endpoint mapping is design §10 with the Task 6 refinement for quick publish. Learner endpoints use authentication only.
- **Fixed numbers (design §2, §5–§11):** upload ≤ 20,000 data rows and ≤ 10 MB; cell ≤ 2,000 chars; lemma ≤ 100; at most 3 example sentences per revision (**plan proposal — the design is silent**; it matches the `example_en_1..3` columns so export → upload never drops examples); search `q` 1–100 chars; `page_size` default 20, max 100; publish list ≤ 500 (`PUBLISH_MAX_ITEMS`); export ≤ 5,000 rows; lease 60 s, heartbeat 20 s, reconciler every 30 s; row retry 3 (exponential backoff with jitter), job attempts 3; stored upload file kept 30 days; levels `A1 A2 B1 B2 C1 C2`; 15 valid `pos` values and the 9 function-word values of design §5.
- **Tests:** real Postgres, Mailpit and Redis via Testcontainers; no mocks of the DB or the queue. Suites that depend on global state (lease, reconciler, queue, counts) use `createIsolatedDatabase()` and a random queue prefix (`config.pipeline.queuePrefix`). Unit specs are `*.spec.ts`, e2e are `*.e2e-spec.ts`.
- **Git:** commit after every task on the milestone branch, Conventional Commits (`feat(content): …`, lower case, imperative). Never push, open a PR or merge unless the owner asks; secrets are scanned before any push.

## Review Focus

1. **Excel-style CSV** — BOM, `;` separator, CRLF, a quoted cell with a line break, a headword starting with `'` (`'m`) — must upload and parse; Task 13.
2. **A cell that starts with `=`, `+`, `-` or `@`** — in an upload and in an export that is uploaded again — must never reach the spreadsheet as a formula and must not change content on the round trip; Tasks 14, 22.
3. **The same file uploaded twice at the same moment under two different `Idempotency-Key`s** — two batches race on the same rows — must leave exactly one entry/level/sense per key and finish both batches; Task 18.
4. **Awkward headwords** — NFC vs NFD spelling of one word, whitespace-only, an emoji, exactly 100 and 101 characters — must normalize to one entry or be rejected with a clear code, never 500; Task 14.
5. **Hostile learner queries** — `%`, `_`, `\`, only spaces, 101 characters, `page_size=0` and `101`, a `page_token` made for another query — must return 400 or a literal match, never an error or a different query's page; Task 8.
