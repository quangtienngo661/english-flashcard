## Global Constraints

- Minimum age **13**; no parental-consent step (D4). Age is computed on "today" in the request's (canonical) time zone; a
  29 February birthday counts as 1 March in a non-leap year (design §4.2).
- `given_name` required at learner registration, `family_name` optional, each **1–50** code points after NFC + trim, no control
  characters; empty `family_name` → null. Staff accounts: both optional (D8).
- `birth_date`: `YYYY-MM-DD`, a real date, **≥ 1900-01-01**, not after "today". Not editable through `PATCH /v1/me`.
- `accept_terms` must be the JSON literal `true`. The server stores `terms_accepted_at = now` and `terms_version =
  TERMS_VERSION` (env, required, e.g. `2026-10-20`).
- `users.status`: `active` | `locked`, enforced by `CHECK`.
- New problem types: `age-below-minimum` (400), `account-locked` (403), `lock-rule` (409). New item/report reasons:
  `revision-rejected`, `sense-unpublished`, `entry-in-use`, `level-confirmed`.
- Logs never carry email addresses, names, birth dates, lock reasons, request bodies or error messages (SR10).
- Time zones are stored as `new Intl.DateTimeFormat('en', { timeZone }).resolvedOptions().timeZone`; offset forms (`+07:00`) are
  refused. On Node 24.11.0 `asia/ho_chi_minh` resolves to `Asia/Saigon` (run 20/10).
- Idempotency: a claimed key holds at most one DB connection at a time; the lease is `@Idempotent({ timeoutSeconds })` (default 30).
- Pool: `DATABASE_POOL_MAX` default **20**, `DATABASE_POOL_TIMEOUT_MS` default **5000** (`ASSUMPTION`, design §11).
- Time-zone formatter cache: at most **500** entries.
- No backend e2e (D13): unit tests (CI) + `pnpm smoke:buoc-0-3-fixes` against a real API on a fresh DB (by hand).
- Admin copy (vi / en), exact:
  - `session.unavailable`: "Không kết nối được máy chủ." / "Cannot reach the server."
  - `session.retry`: "Thử lại" / "Try again"
  - `notice.logoutFailed`: "Chưa đăng xuất được khỏi máy chủ." / "Could not sign out on the server."
  - `errors.code`: "Mã: {code}" / "Code: {code}"; `errors.copyCode`: "Chép mã" / "Copy code"
  - `errors.retryIn`: "Thử lại sau {seconds} giây" / "Try again in {seconds} s"

## Review Focus

1. **A locked learner whose access token is still valid (≤ 15 min)** calls `POST /v1/auth/password/change` with the right
   password → 403 `account-locked`, not a fresh session (Task 13 test "locked user cannot mint a session through password change").
2. **Re-upload of a file whose content rows were applied before, after staff edits** must not create a draft even when the file's
   *level* keys miss (different bytes) and the row goes to the processor (Task 17 test "FE17 through the processor").
3. **An idempotent handler that throws after its own transaction committed** (e.g. a post-commit check): the key is deleted, so a
   retry runs again — the old behaviour, now explicit (Task 2 test "FE30").
4. **Admin bootstrap when the API is down but the refresh cookie is expired**: once the API is back, "Thử lại" must land on `/login`
   ("expired"), not loop on the unavailable screen (Task 21 test "unavailable then 401 → signed-out").
5. **`q` with only spaces** on the admin user list → 400 (trimmed length < 2), not a full-table `ILIKE '%%'` (Task 12 test).

**Interfaces:**

409 `idempotency-key-abandoned`. `failed_permanent` rows still replay (FD8 not in scope).
