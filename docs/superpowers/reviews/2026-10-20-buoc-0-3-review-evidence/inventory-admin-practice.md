- **AD1 and AD2 labelled `decision`.** The code follows design §5 literally (AD1) or covers a case the design does not mention
  (AD2). Changing them changes user-visible session behaviour, so the owner should pick the UX. If the owner considers the 18/10

- **AD7 labelled `bug`.** The fix (re-read `/me` after an identity change) is technical, but "switch the tab to Y" vs "sign the
  tab out" could also be a product choice.
- **PX2 status.** The code is unchanged and the budget is still missed. The owner accepted it in D39 with "re-measure before
  pilot", so it is open but not blocking.
- **PX4 is still SUSPECTED.** No probe was run. Its reach grew: session open (`sessions.service.ts:69-88`) now reads through the
  pool while holding a transaction and the practice advisory lock, and the ~2 s `practiceItems('all')` read runs inside that
  window.
- **PX3 "partial":** this depends on Practice remaining the only caller and on clients never sending a practice item id as a
  flashcard `review_id`. I did not check whether `POST /v1/reviews` would reject that id first (Learning's `reviews.service.ts`
  compares content on reuse, but only for its own stored row).
- No finding was run or probed in this pass. The AD1, AD2, AD8 and PX1 probe outputs date from 18/10. They still apply because
  the code is unchanged (shown by the diffs above), not because they were re-run.
